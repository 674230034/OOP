ใบงานปฏิบัติการที่ 4

เรื่อง ออกแบบระบบชำระเงินค่าเทอม/ค่ากิจกรรมด้วย Strategy Pattern และ Dependency Injection (บริบท: ระบบชำระเงินของมหาวิทยาลัย)
รายวิชา การเขียนโปรแกรมเชิงวัตถุ (PHP 8.4+)

ชื่อ-นามสกุล:
รหัสนักศึกษา:
ชั้นปี/ห้อง:
คะแนน: /50

คำชี้แจง: ให้นักศึกษาศึกษา Class Diagram ด้านล่าง แล้วทำกิจกรรมทุกส่วนให้ครบถ้วน

จุดประสงค์การเรียนรู้:

  • อธิบาย Strategy Pattern และการสลับพฤติกรรมผ่าน Interface ได้
  • ใช้ Constructor Injection เพื่อให้คลาสพึ่งพา Abstraction ได้
  • อธิบายหลักการ OCP, DIP, GRASP Controller และ Protected Variations จากแผนภาพได้
  • ทดสอบการสลับช่องทางชำระเงินและกรณีผิดพลาดได้ถูกต้อง

แผนภาพอ้างอิง

Strategy Pattern DIP OCP GRASP Controller Protected Variations 
classDiagram
    class PaymentMethod {
        <<interface>>
        +pay(amount) string
    }

    class CreditCardPayment {
        <<Strategy>>
        -string cardLast4
        +__construct(cardLast4)
        +pay(amount) string
    }

    class PromptPayPayment {
        <<Strategy>>
        +pay(amount) string
    }

    class PaymentGateway {
        <<DIP>>
        -PaymentMethod method
        +__construct(method)
        +checkout(amount) string
    }

    class InvalidArgumentException {
        <<exception>>
    }

    CreditCardPayment --|> PaymentMethod : OCP
    PromptPayPayment --|> PaymentMethod : OCP
    PaymentGateway --> PaymentMethod : Strategy / DIP
    PaymentGateway --> InvalidArgumentException : Validation
PaymentGateway ทำหน้าที่เป็น Controller/Coordinator และพึ่งพา abstraction แทนการผูกกับช่องทางการชำระเงินจริง

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «interface» PaymentMethod ที่มีเมธอด +pay(amount) : string ทำหน้าที่อะไรในระบบ 2 คะแนน

2) CreditCardPayment และ PromptPayPayment ถูกกำกับว่า «Strategy» จงอธิบาย Strategy Pattern ในระบบนี้ 2 คะแนน

3) ลูกศร “Strategy / DIP” จาก PaymentGateway ชี้ไปยัง PaymentMethod หมายความว่าอย่างไร และเหตุใด Gateway จึงห้ามสร้าง new ของช่องทางชำระเงินเองภายใน 2 คะแนน

4) ป้าย “OCP” บนลูกศรจากทั้งสองคลาสชำระเงินหมายถึงอะไร หากเพิ่มช่องทาง TrueMoney Wallet จะต้องแก้โค้ดส่วนใดบ้าง 2 คะแนน

5) ลูกศร “Validation” ชี้ไปยัง InvalidArgumentException หมายถึงการตรวจสอบใด และอยู่ในเมธอดใด 1 คะแนน

6) PaymentGateway ทำหน้าที่เป็น GRASP Controller อย่างไร 1 คะแนน

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

พิจารณาโค้ดต่อไปนี้ แล้วตอบคำถาม

<?php declare(strict_types=1);

interface PaymentMethod
{
    public function pay(float $amount): string;
}

final class CreditCardPayment implements PaymentMethod
{
    public function __construct(private readonly string $cardLast4 = '0000') {}

    public function pay(float $amount): string
    {
        return sprintf('ชำระ %.2f บาทด้วยบัตรเครดิต ****%s', $amount, $this->cardLast4);
    }
}

final class PromptPayPayment implements PaymentMethod
{
    public function pay(float $amount): string
    {
        return sprintf('ชำระ %.2f บาทด้วย PromptPay', $amount);
    }
}

final class PaymentGateway
{
    public function __construct(private readonly PaymentMethod $method) {}

    public function checkout(float $amount): string
    {
        if ($amount <= 0.0) {
            throw new InvalidArgumentException('Amount must be positive.');
        }

        return $this->method->pay($amount);
    }
}

$gateway = new PaymentGateway(new PromptPayPayment());
echo $gateway->checkout(1500.00);

1) บรรทัดใดแสดง Dependency Injection จงอธิบาย 2 คะแนน

2) ผลลัพธ์ของ $gateway->checkout(1500.00) ในโค้ดบรรทัดสุดท้ายคืออะไร 3 คะแนน

3) หากเรียก $gateway->checkout(-100) จะเกิดอะไรขึ้น เพราะเหตุใด 2 คะแนน

4) หากภายในเมธอด checkout มีโค้ด new CreditCardPayment() โดยตรง จะผิดหลักการใด และส่งผลเสียอย่างไร 3 คะแนน

ส่วนที่ 5: สะท้อนคิดเชิงออกแบบ OOAD (6 คะแนน)

1) ระบบนี้แสดง Protected Variations อย่างไร จุดที่เปลี่ยนแปลงบ่อยคืออะไร และถูกปกป้องด้วยกลไกใด 2 คะแนน

2) การพึ่งพา Abstraction (PaymentMethod) แทน Concrete Class ดีกว่าอย่างไรในแง่การทดสอบและบำรุงรักษา 2 คะแนน

3) หากมหาวิทยาลัยเพิ่มนโยบาย “ผ่อนชำระค่าเทอม 3 งวด” นักศึกษาจะออกแบบส่วนเพิ่มเติมอย่างไร โดยไม่ต้องแก้ PaymentGateway 2 คะแนน
