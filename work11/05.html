จุดประสงค์การเรียนรู้:

  • อธิบาย Repository Pattern และการแยกสัญญาออกจากการจัดเก็บข้อมูลได้
  • อธิบายความแตกต่างของ Entity กับ Value Object ได้
  • เขียน Repository ที่ปกป้องข้อมูลภายในจากการแก้ไขภายนอกได้
  • ทดสอบกรณีบันทึก ค้นหา และคืนข้อมูลทั้งหมดได้ถูกต้อง

แผนภาพอ้างอิง

Repository Pattern DIP Information Hiding Protected Variations 
classDiagram
    class User {
        <<Entity>>
        +int id
        +string email
        +__construct(id, email)
    }

    class UserRepository {
        <<interface>>
        +save(user) void
        +findById(id) UserOrNull

        <<DIP>>
        -array users
        +save(user) void
        +findById(id) UserOrNull
        +all() array
    }

    InMemoryUserRepository --|> UserRepository : Protected Variations
    InMemoryUserRepository --> User : Information Hiding
    UserRepository --> User : Abstraction
Interface ทำหน้าที่เป็น Indirection เพื่อปกป้อง Use Case จากการเปลี่ยนแปลงของเทคโนโลยีการจัดเก็บข้อมูล

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «interface» UserRepository ทำหน้าที่อะไรในระบบ และเหตุใดต้องแยก “สัญญา” ออกจาก “implementation” 2 คะแนน

2) ลูกศร “Protected Variations” จาก InMemoryUserRepository ชี้ไปยัง UserRepository หมายถึงอะไร 2 คะแนน

3) ป้าย “Information Hiding” บนลูกศรจาก InMemoryUserRepository ไปยัง User สื่อความหมายว่าอย่างไร 2 คะแนน

4) User ถูกกำกับว่า «Entity» ซึ่งแตกต่างจาก Value Object อย่างไร จงอธิบายพร้อมยกตัวอย่าง 2 คะแนน

5) เมธอด findById คืนค่าเป็น UserOrNull การคืน null สื่อความหมายว่าอย่างไร 1 คะแนน

6) หากในอนาคตต้องการเปลี่ยนไปเก็บข้อมูลในฐานข้อมูล MySQL โค้ดส่วนใดต้องเปลี่ยนแปลงบ้าง 1 คะแนน

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

พิจารณาโค้ดต่อไปนี้ แล้วตอบคำถาม

<?php declare(strict_types=1);

final readonly class User
{
    public function __construct(
        public int $id,
        public string $email,
    ) {}
}

interface UserRepository
{
    public function save(User $user): void;

    public function findById(int $id): ?User;

    /** @return list<User> */
    public function all(): array;
}

final class InMemoryUserRepository implements UserRepository
{
    /** @var array<int, User> */
    private array $users = [];

    public function save(User $user): void
    {
        $this->users[$user->id] = $user;
    }

    public function findById(int $id): ?User
    {
        return $this->users[$id] ?? null;
    }

    public function all(): array
    {
        return array_values($this->users);
    }
}

$repo = new InMemoryUserRepository();
$repo->save(new User(680001, 'student@example.ac.th'));
$repo->save(new User(680002, 'student2@example.ac.th'));

$student = $repo->findById(680001);
echo $student?->email, PHP_EOL;
echo sprintf('จำนวนนักศึกษาทั้งหมด: %d คน', count($repo->all())), PHP_EOL;

1) เหตุใดเมธอด all() จึงใช้ array_values() แทนการคืน $this->users โดยตรง ป้องกันความเสี่ยงใด 3 คะแนน

2) การเรียก $repo->findById(999999) ให้ผลลัพธ์เป็นอะไร และโค้ดบรรทัดใดรับผิดชอบ 2 คะแนน

3) หาก save ผู้ใช้ที่มี id ซ้ำกับข้อมูลเดิมจะเกิดอะไรขึ้น เพราะเหตุใด 3 คะแนน

4) เหตุใด User จึงเป็น final readonly class การออกแบบนี้ดีต่อระบบอย่างไร 2 คะแนน
