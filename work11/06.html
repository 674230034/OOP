เรื่อง Value Object สำหรับอีเมลนักศึกษา (Email Value Object) (บริบท: ระบบบัญชีนักศึกษาต้องการตรวจสอบอีเมลก่อนสมัครหรือยืนยันตัวตน)

คำชี้แจง: ให้นักศึกษาศึกษา Class Diagram ด้านล่าง แล้วทำกิจกรรมทุกส่วนให้ครบถ้วน

จุดประสงค์การเรียนรู้:

  • อธิบายความแตกต่างของ Value Object กับ Entity ได้
  • ใช้ Static Factory บังคับการตรวจสอบค่าก่อนสร้างวัตถุได้
  • อธิบายความสำคัญของ Immutability ต่อ Value Object ได้
  • ทดสอบการ normalize, การเปรียบเทียบค่า และกรณีผิดพลาดได้ถูกต้อง

Value Object ช่วยให้การ validate และความหมายของอีเมลอยู่ในที่เดียว ลดการกระจายกฎตรวจสอบตาม Service หรือ Controller

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «ValueObject» ที่กำกับคลาส Email หมายความว่าอย่างไร และแตกต่างจาก Entity อย่างไร 2 คะแนน

2) เหตุใด constructor -__construct(value) จึงเป็น private และบังคับสร้างผ่าน +fromString(value) รูปแบบนี้นเรียกว่าอะไร 2 คะแนน

3) “Immutability” หมายความว่าอย่างไร และใน PHP 8.4 ใช้ keyword ใดทำให้ Email เปลี่ยนแปลงไม่ได้ 2 คะแนน

4) ลูกศร “Validation” ชี้ไปยัง InvalidArgumentException หมายถึงพฤติกรรมใด และเกิดขึ้นเมื่อใด 2 คะแนน

5) เหตุใดเมธอด equals(other) จึงเปรียบเทียบด้วย “ค่า” แทนการเปรียบเทียบ identity ของ object 1 คะแนน

6) เมธอด +__toString() มีประโยชน์อย่างไรต่อการใช้งานจริง 1 คะแนน

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

พิจารณาโค้ดต่อไปนี้ แล้วตอบคำถาม

<?php declare(strict_types=1);

final readonly class Email implements Stringable
{
    private function __construct(public string $value) {}

    public static function fromString(string $value): self
    {
        $normalized = strtolower(trim($value));

        if (filter_var($normalized, FILTER_VALIDATE_EMAIL) === false) {
            throw new InvalidArgumentException('Invalid email address.');
        }

        return new self($normalized);
    }

    public function equals(self $other): bool
    {
        return $this->value === $other->value;
    }

    public function toString(): string
    {
        return $this->value;
    }

    public function __toString(): string
    {
        return $this->value;
    }
}

$studentEmail = Email::fromString('Student@Example.ac.th ');
echo $studentEmail->toString(), PHP_EOL;

$anotherEmail = Email::fromString('student@example.ac.th');
var_dump($studentEmail->equals($anotherEmail));

1) ผลลัพธ์ของ Email::fromString('Student@Example.ac.th ') คืออะไร จงอธิบายการทำงานทีละขั้นตอน 3 คะแนน

2) การเรียก Email::fromString('student@invalid') จะเกิดอะไรขึ้น เพราะเหตุใด 2 คะแนน

3) เหตุใด $studentEmail->equals($anotherEmail) จึงคืนค่า true ทั้งที่ข้อความต้นทางต่างกัน 3 คะแนน

4) หากตัด keyword readonly ออก จะเกิดความเสี่ยงใดต่อ Value Object 2 คะแนน

ส่วนที่ 5: สะท้อนคิดเชิงออกแบบ OOAD (6 คะแนน)

1) Email Value Object ช่วยลดการเขียนกฎตรวจสอบซ้ำซ้อน (DRY) ในระบบได้อย่างไร 2 คะแนน

2) เหตุใด Immutability จึงสำคัญต่อ Value Object จงยกตัวอย่างปัญหาหากค่าถูกแก้ไขได้หลังสร้าง 2 คะแนน

3) Email สามารถนำไปใช้ร่วมกับ Use Case อื่น (เช่น RegisterUserService ข้อ 10) ได้อย่างไร และดีอย่างไร 2 คะแนน
